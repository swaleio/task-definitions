# Bash

Writes your `script` to a file and executes it with `bash`, so shebangs,
`set -euo pipefail`, multi-line scripts, and error line numbers all behave
exactly as they do in a normal shell.

## Consuming inputs safely

Every workflow input passed to this task is available as an `INPUT_<NAME>`
environment variable (uppercased). **Reference values through those variables —
do not paste them into the script text** — so quoting and special characters are
handled by the shell rather than by string substitution.

```yaml
tasks:
  build:
    name: Build
    uses: swaleio/bash@1-0-0
    args:
      target: release           # available inside the script as $INPUT_TARGET
      script: |
        set -euo pipefail
        cd /mnt/workspace/app
        echo "Building $INPUT_TARGET"
        make "$INPUT_TARGET"
```

## Emitting outputs

Append `key=value` lines to the file at `$WORKFLOW_TASK_OUTPUT` to publish
outputs for downstream tasks (declare them in a task that needs typed outputs;
this generic `bash` task declares none).
