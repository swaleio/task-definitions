    required: true

  args:

    - ${{inputs.project}}
    - "--ref"
    - ${{inputs.ref}}
    - "--path"
    - ${{inputs.path}}
    - "--dest"
    - /mnt/workspace/${{inputs.dest}}

# Swale pull

Pulls the content of a Swale `project` into `/mnt/workspace/<dest>` using the
Swale client CLI (`swale-cli`), so later tasks in the run can read it from the
shared workspace. Restrict the pull to a single `ref` and/or `path` when you
only need part of a project.

Authentication uses `token`: pass it as a secret. The CLI reads it from the
`INPUT_TOKEN` environment variable rather than from the command line, so the
token never appears in the container's argv or run logs.

> **CLI flags are provisional.** The exact `swale-cli pull` flag names
> (`--project`, `--ref`, `--path`, `--dest`) should be verified against the
> installed Swale CLI and adjusted if they differ. An empty `--ref`/`--path`
> value is expected to fall back to the project default / whole project.

## Inputs

| Input | Required | Default | Description |
|-------|----------|---------|-------------|
| `project` | yes | — | The Swale project to pull from. |
| `ref` | no | default ref | Branch, tag, or commit to pull. |
| `path` | no | whole project | Subpath within the project to pull. |
| `dest` | no | `.` | Destination directory under the workspace. |
| `token` | no* | — | Swale access token (pass a secret). *Required at run time; injected as `INPUT_TOKEN`. |

Because the workspace is shared across concurrent tasks, give parallel pulls
distinct `dest` subpaths so they don't overwrite each other.

## Example

```yaml
tasks:
  fetch_data:
    name: Fetch data
    uses: swaleio/swale-pull@1-0-0
    args:
      project: acme/datasets
      ref: main
      path: images/train
      dest: data
      token: ${{secrets.swale_token}}
```

Downstream tasks read the pulled files from `/mnt/workspace/data`.
